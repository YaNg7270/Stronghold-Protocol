# 离线版实现说明

## 架构

```
浏览器页面 ─────────────────────────────────────────────────────────────
  index.html（打过补丁）
   ├─ /offline/shim.js     把 WebSocket('/ws') 换成 OfflineSocket
   ├─ /js/main.js …        原版客户端，一行未改（界面、PixiJS / Spine / three.js 渲染、本地战斗模拟）
   └─ Worker /offline/worker.js
        └─ offline/server/  本地服务器（纯 ESM，同一份代码也在 Node 测试里跑）
             index.js       会话（hello / welcome / 断线重连）、单人房间、消息分发、存档
             match/Match.js 对局阶段机、战斗下发（b.start）与结算、最终攻势 / 隐秘核心、结果
             match/player.js 资金、生命值、商店、棋子（场上 / 整备区 / 临时整备区）、合成、装备、画卷
             match/pool.js  共享卡池、禁用盟约与禁用干员、商店抽取
             match/bonds.js 盟约人数、阶层、调和
             match/waves.js 波次模板 → 敌人出场，特训敌人替换，敌人强度缩放，悬赏敌人，敌人预览
             match/spdraft.js 机变阶段的卡牌生成
             match/meta.js  准备阶段效果分发（策略、盟约、装备、特质、机变卡、全局效果）及引擎内置效果
```

战斗和原版一样在浏览器里模拟：服务器用服务端提供的 `/sim/spec.js buildBattleSpec` 生成对战描述，客户端的战斗运行器模拟后回报 `b.result`，服务器结算。准备阶段的效果逻辑（`/sim/content/*/meta.js`、`choices.js`）也是服务端提供的原版代码，离线服务器只重建了它们依赖的调度器和 `ctx` 接口。

## 协议从哪里来

线上游戏的 WebSocket 无法从开发环境抓包：出口代理会去掉 `Upgrade` 头，服务器只能看到普通的 `GET /ws`。所以消息格式是从客户端代码里读出来的：`shared/protocol.js` 里有消息目录；`js/store.js`、`js/ui/gameLogic.js`、各个界面组件和 `js/battle/runner.js` 说明了客户端读取哪些字段。规则数值全部来自 `/data/*.json`（`config.json` 的经济、计时、模式、奖励等）。

## 与原版可能不一致的地方（假设清单）

下面这些是原版服务器的行为，但数据和客户端代码里没有写清楚，离线版按最合理的理解实现。

| 项目 | 离线版做法 |
|---|---|
| 隐秘核心解锁 | `config.hiddenCore` 只给出 `single: 350 / multi: 1200`。实现为：击败领袖、团队生命值 ≥ 1，且所有存活玩家**已激活盟约的层数总和** ≥ 350（单人） |
| 普通回合扣血 | 每个计入的漏怪扣 1 点，每回合最多扣 `lpCapPerRound`（10）点，和客户端顶栏的实时显示一致 |
| 回合开始 / 结算 / 协议启动时长 | 2.2 秒 / 3.2 秒 / 3 秒 |
| 战斗速度 | 2 倍速（客户端默认值）。普通回合的期限为时限 ÷ 2 再加 1.5 秒；超过后再等 25 秒，仍收不到结果就由服务器自己模拟（与客户端用的是同一份模拟代码和对战描述，结果一致） |
| 最终攻势 / 隐秘核心 | 单人领袖血量 = `bloodPoint[难度] × 0.25`；120 秒关卡倒计时，150 秒后团队生命值每秒 −1。领袖倒下且团队生命值 > 0 才算胜利 |
| 战术特训悬赏敌人（单人） | 生命值和攻击力 ×0.7（原版注释只写了「solo ×0.7」） |
| 引擎内置的装备效果 | 盟约之币、骑士储蓄罐、随身身份牌、紧急调度券、精打细算玩偶、简易通讯机、见钱眼开玩偶、信标、拟态物质、博士投影、商业包装方案、突变细胞、人事部文档，以及教鞭 / “神秘顾客”的兜底悬赏，按道具描述重写。原版代码中能找到的覆盖逻辑（`items/meta.js`）照常生效 |
| 投资人 | 激活时“获得时”特质触发 2 次，达到 100 层后触发 3 次 |
| 评语（单人） | 胜利且对领袖造成过伤害 → 卫戍之星；否则依次按晋升 ≥ 4、激活层数 ≥ 60、剩余生命值 ≥ 20、配发装备 ≥ 6、消耗资金的条件取第一个满足的 |
| 临时整备区 | 不为空时不能准备就绪（和原版一致）。万一准备阶段结束时还有棋子，会被自动出售 |
| 同盟模拟 | 不支持（创建房间时会提示改选独立模拟） |
| 网络延迟显示 | 显示的是页面与本地 Worker 之间的往返时间 |

## 存档

服务器状态（会话、房间、进行中的对局）每 2 秒以及离开房间时写入 IndexedDB（`stronghold-offline`）。页面刷新或关闭后重新打开，客户端会用会话 token 重新连接，服务器把房间、对局状态和进行中的战斗重新发给客户端（战斗按经过的时间快进到当前进度）。

## 测试

- `npm test`：经济（收入、购买、出售、刷新、冻结、升级）、三合一与晋升奖励、放置规则、战斗接管、服务器重启后恢复对局、断线重连、机变阶段。
- `node test/play.mjs <难度> <种子> [--rich]`：无界面整局对战。机器人每次战斗都用真实的模拟代码跑完；`--rich` 会额外给资金，用来覆盖最终攻势和隐秘核心。
- `npm run e2e -- --rounds N [--reload]`：Chromium 跑真实客户端，屏蔽所有非本机请求（证明不需要联网），每个阶段截图；`--reload` 会在准备阶段和战斗中各刷新一次页面，检查能否恢复。
